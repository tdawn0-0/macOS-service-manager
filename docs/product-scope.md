# Product scope: software, databases, and HTTPS

Status: current resource-product contract, defined in 015-A on baseline `2ec48ab` and extended by 018 after the 011–017 worktree chain. Code-level checks pass; full native and system-trust/Chrome acceptance remain **NOT RUN**. See [resources-acceptance.md](resources-acceptance.md) for observable checks.

## Primary navigation

The app has three primary entries under **Workspace**: **Software**, **Databases**, and **HTTPS** (also reachable via `Cmd+1`–`Cmd+3`), plus a workspace live log drawer (**Logs** / **Live logs**). The existing system-service inspector (**All Items** under **Inspector**, **Apps & Services**, and **launchd**) remains a secondary capability; **Settings** opens via the sidebar or `Cmd+,`. The menu bar shows independently managed database instances (with **Stop all** when running), one HTTPS proxy, and a failed-resource badge in the header/tooltip when any workspace resource fails; installed software and the number of proxy rules are not running-process counts. All workspace, inspector, and settings capabilities are also exposed headlessly through the public `devbase` CLI (`--json`, `devbase schema`, stdin-only secrets, and Settings `Command-line interface` wrapper installation in [cli.md](cli.md)), while `devbase gui`/`open` or empty arguments launch the desktop window and `--dev` remains reserved for internal `launchd` helpers.

Software installs and manages verified versions of Node.js, Java, Python, MySQL (`8.4` and `8.0` LTS), PostgreSQL, Redis, and MongoDB (`8.0` and `7.0`). PostgreSQL and Redis come from Homebrew core. Java installs macOS arm64 JDK distributions from the JetBrains JDK catalog in `~/Library/Java/JavaVirtualMachines` with exact upstream hashes, and automatically loads its catalog when visited (with **Refresh available versions** kept). Python delegates installation, enumeration, and removal to uv (with optional native file selection) and shares its standard store, automatically loading installed/available versions on visit. Selecting a version in Software previews package details asynchronously. Other archive-managed software retains its verified sources, and Settings exposes download cache size and cleanup without disturbing installed packages. Node.js and Java surface newer same-series catalog updates for explicit review. Node.js and Java retain per-directory version declarations without registering the directory: Node.js checks `.node-version`, `.nvmrc`, or `package.json` `engines.node`, and Java checks `.java-version` or `.sdkmanrc` (`java=<spec>`) against Apple Silicon JDKs in `~/Library/Java/JavaVirtualMachines` before falling back to the configured default. Terminal integration is explicit and reversible for installed zsh, Bash, and fish; Java also sets `JAVA_HOME`. Python’s default action changes the global uv pin, preserving directory pins and virtual-environment precedence. It does not replace the shell’s python command. Software installation alone does not imply that a new terminal uses the version. PHP installation, version selection, repository setup, and terminal integration leave the product; existing PHP installations on the machine are not removed.

Databases owns independent MySQL, PostgreSQL, Redis, and MongoDB instances. Each has its own exact installed package, state, data, port, lifecycle, credentials, and background operations. New instances can use a new absolute external data location (entered directly or derived from a selected parent folder); the parent must exist and directory symlinks, overlapping paths, and existing directories are rejected. Ownership markers and directory identity are checked before data operations. Remove keeps external data. External permanent deletion is disabled, while app-managed data retains the reviewed recovery transaction. There is no automatic adoption, relocation, or in-place major upgrade. A stopped MySQL, PostgreSQL, Redis, or MongoDB instance can be moved to a newer installed patch or revision release of the same series (e.g., `8.4.x`, `17.x`/`17.x_rev`, `8.2.x`); moving between series/major lines and downgrades are not supported. Start, stop, restart, initialization, live database/user inspection, database/user creation and confirmed **Drop database** / **Drop user** (rejecting system databases and built-in/admin users), backup (with existing database selection), restore into a specified target database, Console/live-drawer log access, **Open CLI in Terminal** (`psql`, `mysql`, and `redis-cli` via `0700` `open-cli.command` scripts reading private credential files without placing secrets in `argv`), and deletion act on the selected instance, with data and busy-operation safeguards. Connection profiles belong to an instance and store no business password; URI, engine-appropriate `.env` (`DATABASE_URL`, `REDIS_URL`, `MONGODB_URI`), and JDBC exports remain password-free. Deleting a profile does not delete a real database or user.

HTTPS provides a single configuration page with a table of **Domain → Local port** rules (with an active listening local port picker for current-UID TCP `LISTEN` ports `>= 1024`, excluding the proxy listener and managed database ports); a domain is always `<name>.devbase.localhost`, which macOS resolves to this Mac, so the app never edits the hosts file or DNS. Each rule forwards to `http://127.0.0.1:<LocalPort>`, or to `http://<UpstreamHost>:<LocalPort>` when the rule names an IP address or host name, and can optionally provision its own dedicated Cloudflare Worker + Durable Object (`devbase-<slug>`) via the Cloudflare API, exposed either on `*.workers.dev` or a bound Cloudflare Custom Domain, with optional Worker edge access-token protection stored in a private `0600` file (`proxy/tunnel-access.json`) outside `state.json`. The Cloudflare API token field is masked with a required-permissions tooltip; **Save Cloudflare settings** automatically attempts account/zone discovery when a token is saved or Account ID is blank, and **Remove Cloudflare token** stops the tunnel and clears `proxy/cloudflare.key` and saved Cloudflare account metadata after confirmation. The HTTPS listener port is global and defaults to 443. Rules have no separate resource ID, detail page, or upstream process lifecycle. Save commits the whole validated table and listener port (and reconciles Cloudflare Workers when an API token is configured); Apply publishes the saved configuration to the proxy/tunnel, and **Save & apply** performs both steps together. Both the local HTTPS proxy and Cloudflare tunnel run as background `launchd` jobs with dedicated start/stop switches, live per-rule worker state tags (`Tunnel connected`, `Tunnel connecting`, `Tunnel conflict`) while running, log viewers, and quick URL copy/open menus on the HTTPS tab and in the menu bar. **Local certificate trust** shows an inline CA trust status badge (`Trusted`, `Not trusted`, or `Not created`) and warns if the proxy runs while untrusted; local CA trust remains a separate, explicit privileged action. A published configuration is not proof that DNS, TLS, the upstream, or an HTTP response works; local and tunnel HTTP response probes run only on explicit request. Stopping the proxy or tunnel does not stop any upstream app or delete saved rules or deployed Cloudflare Workers. The app does not start or manage the upstream process; users start it in their terminal or IDE.

## Lifecycle and safety

Closing the window leaves managed work running. Quitting leaves background HTTPS proxy and Cloudflare tunnel `launchd` jobs running without prompting; when managed databases or unsaved edits are present, Quit offers a clear choice to keep managed resources or stop selected app-owned database jobs. Settings also provides **Start at login in menu bar**, managing `xyz.jyeu.devbase.login.plist` (`--background`, starting with the main window and Dock icon hidden). Authorization and trust must be shown as separate operations. The app does not take ownership of unrelated processes, system services, Homebrew kegs, hosts entries, or certificates. Root operations (privileged proxy listeners, system daemons, Homebrew services registered as root) require the privileged helper, which is installed once with an administrator password and only serves the Devbase build it was installed from, running as the installing user. Legacy state is rejected without silent conversion or overwrite. This product revision has no old Project schema migration or compatibility layer; tests use a fresh isolated state root. Devbase (`xyz.jyeu.devbase`) is also a new bundle for users of the released macOS Service Manager v1.0.0 (`xyz.jyeu.msm.app`), and it deliberately imports nothing from it: that app kept only its window frame, a `welcomed` marker and a cache of the last `sfltool dumpbtm` answer, so after the upgrade the window opens at its default size and Login Items helpers show again after one refresh. Devbase opens on the development workspace and shows no welcome guide; the Full Disk Access guide opens only from Login Items. The old app is a separate bundle and is not removed. Removing old features is not authorization to delete real databases, shared software, or unknown jobs on a user's machine.

## Explicitly outside scope

Project registration, source-directory management, command execution, dependency installation, app orchestration, project autostart, environment import/export, Go runtime management (Go SDK version management uses Go's native toolchain resolution and is outside scope), PHP, independent site management, arbitrary remote upstreams, FastCGI, SQL IDE, cloud sync, and team environment sharing. The existing secondary system-service capability remains available under its own controls.
