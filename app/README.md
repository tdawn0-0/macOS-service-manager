# app — Devbase's native shell

Devbase's desktop UI, migrated from Go/mygo to [Native Shell](https://nsh.dev)
(longbridge/nsh). This is the product: **pure Rust**, no TSX, no QuickJS, one
NSH app with a native AppKit window. The Go tree was deleted at the Phase 5
cutover; `app/crates/` and this crate are the whole application.

The window is configured at 1100×720 (minimum 900×520) with a sidebar of six
sections: Services, Development, Databases, HTTPS Proxy, Diagnostics, Settings.
All six are implemented, and `src/menubar.rs` draws the menu-bar panel.

## Layout

```text
app/
├── nsh.json              name, id, version, crate root, theme, window, macOS packaging
├── theme.json            design tokens (shadcn cssVars: colors, radii, fonts)
├── Cargo.toml            the app's crate (nsh-core, nsh-base, the macOS backend)
├── src/
│   ├── lib.rs            root component `App` and the `#[native_module]` UI set
│   ├── main.rs           `cargo run`: the same root on this machine's backend
│   ├── meta.rs           name, identifier, version, minimum macOS
│   ├── theme.rs          Rust bindings for the tokens (surfaces, spacing, type)
│   ├── shell.rs          the shell: sidebar beside the workspace
│   ├── launch.rs         public CLI and internal `--dev` dispatch
│   ├── menubar.rs        menu-bar/tray panel
│   ├── guide.rs          first-run guide
│   ├── logs.rs           the live workspace log drawer
│   ├── components/       shared layout, controls, sidebar, status dot, icons
│   ├── pages/            services, development, software, databases,
│   │                     https_proxy, diagnostics, settings (each a module)
│   └── store/            signal-backed state per feature
├── tests/                headless shell and screen tests
├── crates/devcore/       system core: launchd, state, operations, software,
│                         databases, shell, diagnostics, privileged helper
├── crates/devproxy/      HTTPS proxy, local CA, Cloudflare tunnel
├── crates/devcli/        public and internal CLI
├── .nsh/                 generated by nsh (ignored): runners, build output
└── target/               Cargo's build directory (ignored)
```

`nsh.json`'s `"root": "App"` names the root component; `nsh run` and
`nsh package` mount it with no JavaScript VM. The `#[native_module]` in
`src/lib.rs` is the crate's UI set for the day a TSX entry is added; nothing
under this app is TSX today.

## Build and run

Run these from `app/` (or pass the directory from the repository root).

```sh
nsh build                     # compile the crate and the app's hosts; writes .nsh/out
nsh run --target macos        # build and open the AppKit window; rebuilds on Rust edits
cargo run                     # the same root directly, through src/main.rs
cargo test                    # unit tests plus the headless shell tests
```

The first build compiles the crate and NSH's core (about a minute); later
builds are incremental. `nsh` is pinned to `>=0.6.1, <0.7` by `nsh.json`'s
`"nsh"` key, and the `nsh-*` crates in `Cargo.toml` match that version. Upgrade
them together.

Packaging uses the same directory:

```sh
nsh package --target macos
```

It writes an ad-hoc signed `Devbase.app` under `.nsh/out/` with bundle
identifier `xyz.jyeu.devbase`, `LSMinimumSystemVersion` 26.0 and the Apple
Events entitlement. `macos.infoPlist` and `macos.entitlements` in `nsh.json`
are the only place to change those; there is no separate plist file. The
release script re-signs and notarizes the packaged app.

## Theme tokens

`theme.json` is the one place raw colors live. It uses shadcn's `cssVars`
format (`theme`, `light`, `dark`). The values were ported from the old Go app:

| Old Go token | Token | Rust |
|---|---|---|
| `glassTone.sidebarSolid` | `sidebar` | `theme().sidebar` |
| `glassTone.pane` / `sheet` | `background` / `sheet` | `theme().background`, `theme::sheet()` |
| `glassTone.panel` | `panel` | `theme::panel()` |
| `glassTone.edge` | `border` | `theme::hairline()` |
| `glassTone.hover` / `selected` | `row-hover` / `sidebar-accent` | `theme::row_hover()`, `theme().sidebar_accent` |
| `glassPanel` radius 12 | `radius-panel` | `theme::panel_radius()` |
| `t.Spacing = 3.5` | `spacing` | `theme::space(n)` |
| `textSmall` 12 / `textCaption` 11 | (Rust constants) | `theme::TEXT_SMALL`, `theme::TEXT_CAPTION` |

Lobe UI's semantic roles map to shadcn's `primary`, `secondary`, `muted`,
`accent`, `destructive`, `border` and `ring`, plus the app's own `success` and
`warning`. Screens read colors through `src/theme.rs` or `theme()` and never
write a hex value, a font size or a radius at the call site. Both appearances
are defined, and color bindings are closures (`.bg(move || theme().panel)`) so
they follow a live appearance change.

`Typed style` methods follow Tailwind's default 4pt scale; `theme::space(n)` is
the port of the Go app's 3.5pt step for the shell's layout.

## Add a Rust component

Components are plain functions that return elements. Put one in its own module
under `src/components/` and export it from `components/mod.rs`.

```rust
// src/components/status_dot.rs
use nsh_base::theme;
use nsh_core::prelude::*;

use crate::theme as tokens;

/// A solid dot for a running service, hollow at rest.
pub(crate) fn status_dot(running: Signal<bool>) -> impl IntoElement {
    view()
        .size(px(8.0))
        .flex_none()
        .rounded(px(4.0))
        .bg(move || {
            if running.get() {
                theme().color("success").unwrap_or(theme().primary)
            } else {
                AdaptiveColor::TRANSPARENT
            }
        })
        .border_1()
        .border_color(move || theme().color("success").unwrap_or(tokens::hairline()))
}
```

```rust
// src/components/mod.rs
mod status_dot;

pub(crate) use status_dot::status_dot;
```

Then call it from a page or the shell: `.child(status_dot(running))`, where
`running` is a `Signal<bool>`.
Use `theme::space(n)` for padding/gaps, `theme::panel_radius()` for cards, and
`px(tokens::TEXT_BODY)` (13) or `px(tokens::TEXT_SMALL)` (12) for text.

If the component owns state (signals, effects, timers), make it a
`#[component]` with a `#[derive(Props)]` struct and, only when a TSX entry
imports it, register it in `#[native_module]` in `src/lib.rs`. The current app
has no TSX entry, so registration is not needed for Rust-only screens.

## Add a store module

State lives behind functions, as in `src/store.rs`: the signal is private,
pages read and change it through exports. A global is one per surface, so
every `nsh run` and headless test starts fresh.

```rust
// src/store.rs (or a module beside it)
use nsh_core::prelude::*;

#[derive(Clone, Default, PartialEq)]
struct Filter {
    query: String,
    running_only: bool,
}

fn filter() -> Signal<Filter> {
    global::<Filter>()
}

/// The active filter (tracked where it is read).
pub(crate) fn filter_query() -> String {
    filter().with(|f| f.query.clone())
}

/// What the list shows: setting this re-runs the bindings that read it.
pub(crate) fn set_filter_query(next: &str) {
    filter().update(|f| f.query = next.to_owned());
}

/// A derived value read from a plain function is not retained. A screen that
/// needs one creates it once in its component body:
/// `let filtered = computed(store::filter_query);` and
/// `effect(move || log::info!("filter: {}", filtered.get()));`.
pub(crate) fn has_filter() -> bool {
    filter().with(|f| !f.query.is_empty())
}
```

Use `signal`, `computed`, `effect`, `batch` and `untracked` from
`nsh_core::prelude`. `computed` and `effect` are owned by the component (or
the store) that creates them: create them once in a component body, never
inside a getter called from a binding. Keep signals private; export reads
(`fn`) and writes (`fn`) so a page never owns another page's state. For a
per-component value, create the `signal` inside the component body instead of
a global.

## Add a screen

1. Create `src/pages/<name>.rs` returning `impl IntoElement`, composing the
   shared components and the store.
2. Add `mod <name>;` and `pub(crate) use <name>::<name>;` to `src/pages/mod.rs`.
3. Add a variant to `Section` in `src/store.rs`, include it in `Section::ALL`,
   and fill `label()`, `summary()` and `lands()`. The sidebar renders
   `Section::ALL`, so the row appears automatically.
4. Add a `when` branch in `src/shell.rs`'s `workspace()`:

```rust
.child(when(
    move || store::active_section() == Section::Services,
    pages::services,
))
```

Pages never draw the window or the navigation rail; the shell owns those. The
workspace is one opaque `sheet`; pages draw a page header and `panel` cards.

## Notes

- All product code lives under `app/`; the repository root holds docs, scripts,
  licenses and icon sources.
- System interaction (launchd, brew, databases, proxy, CA, tunnel, privileged
  helper) lives in the Rust crates, not the pages. Export only what a screen
  needs.
- The app is macOS 26+ on Apple Silicon. Do not add compatibility paths for
  older systems.
- Keep the safety invariants: never delete external data directories, no
  plaintext secrets in argv, the Cloudflare token never in `state.json`, and
  privileged work only through the helper.
