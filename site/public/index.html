Questions.

Technical details on architecture, local trust, and safety guarantees.

GitHub Issues →
Why macOS 26+ on Apple Silicon only?+
Devbase targets darwin/arm64 and the two latest macOS releases (26 and 27) using native NSGlassEffectView APIs. That keeps the notarized Rust app at 16.9 MB with zero legacy fallback or Intel binary weight.
How does local HTTPS work without editing /etc/hosts?+
Every rule uses <name>.devbase.localhost, which macOS resolves directly to 127.0.0.1 per RFC 6761. Devbase routes TLS via SNI on port 443 without modifying /etc/hosts or system DNS.
How do Node.js and CLI tools trust the local CA?+
Browsers trust the generational root once confirmed in macOS Keychain. Reversible shell hooks export NODE_EXTRA_CA_CERTS and CLI CA variables pointing to Development/proxy/ca.pem.
What happens to external database directories on remove?+
External data directories are always retained. Permanent deletion of external data is deliberately unsupported in both the UI and CLI.
Is devbase mcp safe for coding agents?+
Yes. devbase mcp is strictly read-only over stdio, exposing 7 inspection tools with zero destructive actions and zero plaintext secrets returned.
Why does Devbase use a privileged helper?+
Port 443 binding, system launchd daemons, and root Homebrew services run through a small idle-exit helper bound strictly to the exact Devbase build and user that installed it.
