## 默认 443 与 launchd socket activation 实测

2026-11-06，默认地址 https://service-manager-verify.test/ 已在原生 Google Chrome 正常显示 PHP 测试页；网站信息弹窗明确显示“连接是安全的”。地址没有显式端口，未使用任何证书警告绕过。

系统任务配置位于 /Library/LaunchDaemons 的本应用专属标签下，由 root 拥有，权限 0644。launchd 只在 127.0.0.1 创建 IPv4 TCP 443 监听，并以 jyeu（UID 501）启动代理。通过 lsof、launchctl print 和代理启动日志分别核对了监听地址、运行用户及进程 UID。代理从 launch_activate_socket 获取已绑定描述符，不以 root 运行。

代理入口复制到 App 数据目录 helpers/proxy，避免依赖临时 CLI 路径或应用包移动。系统任务更新使用授权命令内嵌的不可变 plist 字节，不在授权后从用户可修改的暂存文件读取系统任务配置。网络失败时恢复之前的路由和任务。

为减少测试期间输入密码，新增 proxy-verify：在一次管理员授权内完成解除注册、等待进程退出、检查所有监听端口已经释放、恢复系统任务并重启。随后由普通用户完成可信 TLS 握手。此次批量测试成功，结束后系统 curl 请求返回 PHP 页面，代理启动日志再次确认 UID 501。

新增真实协议回归测试覆盖 WebSocket 升级与帧回显、SSE 首块即时传输、约 2 MiB 上传摘要一致。go test -race ./... 与 go vet ./... 通过。

实现依据：[Apple 的 launch_activate_socket 文档](https://developer.apple.com/documentation/xpc/launch_activate_socket)及 [launchd 任务和 socket 配置说明](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html)。

此项验证完成；整个首版仍需按剩余功能清单继续审计，不能将 443 验证等同于全部需求已完成。当前保留验证站点和本应用网络任务供后续图形界面联调，未关闭系统的认证或证书验证保护。

Safari 实机补测：同一默认地址在原生 Safari 正常打开，窗口可访问性状态明确为 IsSecure=true，页面显示 PHP 8.5.12 和本地 HTTPS 验证成功内容，没有安全警告绕过。Chrome 与 Safari 的默认 443 验证均已完成。

## 服务就绪、重启策略和状态刷新（2026-11-07）
