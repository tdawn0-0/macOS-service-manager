Frequently Asked

Clear answers, no hand-waving.

How Devbase handles macOS 26 APIs, local CA certificates, external database safety, permissions, and AI agent integration.

Ask on GitHub Issues →
Platform & Networking
Why macOS 26+ on Apple Silicon only? +
Devbase targets only Apple Silicon (darwin/arm64) and the two latest macOS releases (currently macOS 26 and 27). Focusing strictly on current Apple hardware and macOS 26 Liquid Glass APIs keeps the bundle at 16.9 MB with zero legacy fallback branches or Intel fat-binary bloat.
How does local HTTPS work without editing /etc/hosts? +
Every local proxy rule uses a <name>.devbase.localhost domain. macOS resolves *.localhost directly to loopback (127.0.0.1) per RFC 6761, so Devbase routes HTTPS via SNI without ever writing to /etc/hosts or installing a custom DNS resolver.
How do Node.js and CLI tools trust the Devbase local CA? +
Browsers use the macOS trust store once you explicitly confirm local CA trust. For Node.js and terminal runtimes that maintain their own CA bundle, Devbase's optional, reversible shell integration (zsh, Bash, or fish) exports NODE_EXTRA_CA_CERTS pointing to the active Devbase generational root certificate.
Data Safety, Permissions & Scope
What happens to my external database directory if I remove an instance? +
External data directories are always retained when you remove an instance. Permanent deletion of external directories is deliberately unsupported in both the UI and CLI so developer data can never be accidentally wiped. App-managed data directories use a reviewed recovery transaction with explicit fingerprint confirmation.
Why does Devbase ask for a privileged helper or Full Disk Access? +
Root actions—binding port 443 for local HTTPS, managing system launchd daemons, or controlling root-owned Homebrew services—run through a small privileged helper installed once with your administrator password. It accepts requests strictly from the exact Devbase build and user that installed it, and idles out when unused. Full Disk Access is only prompted if you inspect macOS Login Items via sfltool.
Does Devbase start my web app servers, or manage PHP and Go? +
No. Devbase deliberately keeps a clean boundary: it manages foundational runtimes (Node.js, arm64 Java JetBrains JDK, Python via uv), isolated database instances, local HTTPS forwarding, Cloudflare tunnels, and CAs. You start your own app server in your terminal or IDE. PHP, Go runtime management, and project registration are intentionally outside scope.
AI Agents, CLI & Security
Is devbase mcp safe to connect to Claude Code, Cursor, or Antigravity? +
Yes. The built-in stdio MCP server (devbase mcp) is strictly read-only. It exposes 7 inspection tools (status, database list, password-free connection strings, bounded log tails, active ports, redacted diagnostics, and service listings) with zero destructive mutations and zero plaintext secrets returned.
How are database passwords and Cloudflare API tokens passed to the CLI? +
Devbase rejects plaintext secret flags like --password or --token on the command line immediately with exit code 2 so secrets never leak into shell history or process lists. Credentials are piped exclusively via stdin (--password-stdin, --token-stdin) and stored in private 0600 files outside state.json.
